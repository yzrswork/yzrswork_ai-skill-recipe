AI OPERATING MODEL / 2026

AIは手を動かす。
人間は理由を持つ。

や印工務店では、アイデアを思いつきで終わらせない。AIと人間が共通の記録と手順を参照し、制作・検証・公開・改善を続けています。

大切なのは「どのAIを使ったか」ではなく、何を任せ、どこで判断し、何を次の仕事に残したか。

01 / THE MODEL

頭脳をひとつにしない。
判断の基準を共有する。

人、AI、ツールを一体化しない。仕事の責任と手順を分けることで、使うAIや実行環境が変わっても、仕事の考え方が残ります。

01 / OWNER

人間DIRECTION & OWNERSHIP

目的と境界を決める。 何を作るか、やらないか、許可が必要な操作は何か。AIの提案を採用するかも、人間の責任で判断します。

02 / SKILL & CONTRACT

共通の手順RULES BEFORE TOOLS

作業の進め方を定義する。 入力、完成条件、禁止事項、確認方法をSkillや規約に置き、AIごとの思い込みや手順の省略を防ぎます。

03 / AGENT

AIと実行環境EXECUTION & VERIFICATION

許された範囲で実行する。 調査、制作、編集、検証、差分の提示を担当。権限や環境が足りなければ、推測で突破せず停止します。

02 / WORK FLOW

仕事を進める。
そして、理由を残す。

これは代表的な仕事の流れを示した概念図。作業によって手順や承認点は異なり、すべてを自動で順番に実行するわけではありません。

※ GitHubのbranch → PR → mergeは変更を運ぶ仕組み。PRやmerge自体が、人間の承認を意味するわけではありません。承認条件は対象業務の規約で決まります。

03 / BOUNDARIES

任せることと、
止まることを決めておく。

AIを使いこなすとは、何でも実行させることではない。可逆な作業を進めやすくしつつ、重要な境界で無断変更を防ぎます。

DELEGATED / 契約で許される範囲

AIが進められる仕事

  • 情報の調査と整理、比較案の作成
  • 制作案・文章・コードの下書き
  • 可逆なVault内部更新（適用される規約の範囲内）
  • テスト・差分確認・未確認事項の報告

できることは接続権限・作業環境・個別Skillによって変わります。

HUMAN GATE / 条件付きで停止

人間が判断する境界

  • 公開・配信など、明示許可が必要な操作
  • 作業範囲を超える変更や設計方針の変更
  • 規約上、Owner確認を要求する書き込み
  • 根拠が不足し、推測が必要になる判断

すべての操作に一律の承認を要求するのではなく、業務別の契約を優先します。
