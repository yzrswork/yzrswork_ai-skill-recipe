# 作業ログ 2026-11-27

## 概要
X Bookmark Logger（本体 1.1.0 / アップローダー 1.1.0）の重複防止を、投稿IDでの照合に強化した。

- ブランチ: `claude/x-bookmark-dedupe-by-id`
- 対象: `x-bookmark-logger.user.js` / `x-bookmark-uploader.user.js` / `x-bookmark-logger.html`
- 追加: `tests/x-bookmark.test.mjs` / `.github/workflows/x-bookmark-tests.yml`

## 直した問題

1. 投稿者がハンドル名を変えると、同じ投稿が別名で2回保存される。
   ファイル名に screen_name が入るため、パスが変わって 422（同名ファイルあり）の防止が効かない。
   保存先のVaultで実例2組を確認した（2026-11-27に削除済み）。どちらも記録済み索引を持たない端末の差分同期で起きた。
2. Vault側で `archive/` へ移したクリップが、記録済み索引を持たない端末の差分同期で直下に作り直されうる（コードからの推定）。

## 変更

- 送信の前に GitHub trees API で保存先フォルダ（サブフォルダを含む）の一覧を取り、ファイル名の末尾 `_<投稿ID>.md` から投稿IDを集める。
  同じIDがあれば保存せず、記録済み索引に入れてキューから外す。
- 一覧の取り方: ブランチの最上位ツリーから保存先フォルダを1段ずつたどり、最後にそのフォルダを `recursive` で取る（`xBookmarks` なら1回の送信につきGET 2本）。
  `tree_sha` にブランチ名を渡す方法は公式ドキュメントに記載がある。`main:xBookmarks` のような書き方は記載が無いので使わない。
- 一覧を取れないとき（通信エラー、401/403/404、5xx、上限での切り詰め）は送らずにキューに残し、エラーを表示する（owner判断: 重複防止を優先）。
- 必要な権限は Contents の read（公式の fine-grained PAT 権限表で確認）。既存の「Contents: Read and write」で足りる。
- 導入ガイドの重複防止の説明を更新し、取得失敗時の対処と、リポジトリから消したクリップは再取り込みされうることを追記。

## iOS 対応の廃止（本体 1.2.0）

ownerはPCからしか取り込んでいないため、iOS（Userscriptsアプリ）向けの対応を外した（owner指示）。

- `x-bookmark-uploader.user.js` を削除した。GitHub Pages からも配信されなくなる。
- 本体から、アップローダー向けの通知（`xbm:queue` イベント）と送信能力のフラグ（`xbm.cap_gm`）を外した。GM_xmlhttpRequest が無い環境では送らず、エラーを表示してキューに残す。
- 導入ガイドから iPhone の導入手順とアップローダーのボタンを外し、スマホでブックマークした分は PC のブラウザで `x.com/i/bookmarks` を開いて取り込む説明にした。
- テストは本体だけにした（13件PASS）。GM_xmlhttpRequest が無い環境のテストを足した。
- これで、動画のMarkdown出力の本体とアップローダーの相違も無くなった。

## 申し送り

- リポジトリから削除（PRUNE）したクリップは照合の対象外。X側のブックマークが残っていると、記録済み索引を持たない端末の差分同期で再び取り込まれる。
  対策（除外IDの一覧ファイル、または削除時にX側のブックマークも外す運用）は、最初の削除判断の前に決める（owner判断: 今回は入れない）。
